# No-Skill Baseline

## Purpose

This file preserves the observed RED baseline for the three reusable scenarios in `scenarios.md`. The observations below describe responses produced without the designing-engineering-learning-phases Skill. They are comparison evidence, not target behavior.

## Observed results

The observed no-Skill baselines are recorded exactly:

```text
Transformer reverted to Day 1-Day 7 despite flexible pacing.
Python CLI made a strong ladder but omitted node classification and unequal-intensity justification.
Linux made a strong gate ladder but treated gates uniformly and omitted global importance.
```

## Rubric interpretation

| Scenario | Preserved strength | Decisive RED gaps |
| --- | --- | --- |
| Transformer mechanism learning | Produced a recognizable sequence of learning work. | Violated flexible phase pacing by reverting to Day 1-Day 7; therefore it fails phase-output and scenario-fidelity invariants. |
| Python CLI application boundaries | Produced a strong task ladder. | Omitted knowledge-node classification and current/target depth, and did not justify unequal evidence intensity. |
| Linux process and signal diagnosis | Produced a strong gate ladder. | Treated gates uniformly instead of calibrating intensity and omitted explicit P0-P3 global-importance ranking. |

The baseline remains RED if any hard invariant in the compact rubric is missing, even when its ladder or gates are otherwise strong. Future Skill-assisted runs should be compared against the same prompts and scored 7/7 without weakening the invariants.
